# 任务计划改造技术债

更新时间：2026-08-21

## 当前最小交付

- 新建手动计划以 `TaskContext` 快照作为唯一事实源。
- `plans` 与 `plan_steps` 仅保留现有桌面 API/UI 的兼容投影。
- 执行、暂停、恢复、取消和 Consent 拒绝均先更新快照，再刷新兼容投影。

## 后续技术债

1. 升级前仅存在于 `plans`、`plan_steps` 的未完成计划目前只能读取状态，不能自动迁移为可执行快照；后续需要一次性迁移器。
2. 手动计划仍使用 `_legacy_plan_step_invoker()` 生成模拟执行结果，尚未接入真实 Skill、Tool 或 Capability 执行器。
3. 手动计划控制接口尚未全部复用核心 `resume()` 与 Consent 决策入口，以保持现有“恢复但不立即执行”的 UI 契约。
4. 兼容投影目前在请求线程同步刷新，后续应改为快照事件驱动的 Projection。
5. Auto 计划 SSE 尚未统一到持久化事件流与 seq gap repair。
6. LLM 拆解结果尚缺少“用户目标—步骤内容”相关性门禁；短问候可能被误拆成无关编码任务。后续应增加一致性校验与用户可见降级，未验证候选继续禁止进入注入池。
