## 0. 目标

persona 从“记录标签”升级为“输出硬约束”，实现温柔 / 暴躁 / 可靠 / 甜美 / 可爱五个人格的输出风格可辨、可验证、可回退；风格鲜明度严格不兑换语义完整性，核心能力指标不低于基线。

- 量化目标：人格盲判识别率逐对方向显著 + 70% 参考线（判定主体 = 外部校准均值）；
- 刚性底线（分层承诺）：批级红线判例集（含对抗性）违规 = 0【硬可测】；运行时模式化形态 fixture 召回全绿【可测】；开放空间纵深防御【无 0 承诺，warning 观测记档】；
- 工程要求：约束层关闭后输出与同 seed 无约束路径逐字节一致。

## 1. 核心架构裁决

### 1.1 trait 双类型：风格型与行为型本质分离

- 风格型（温柔/暴躁/甜美/可爱）：语气表达层——语气词带、句长节奏、标点习惯、情绪色彩。走风格通道；C 维全部中位（人格风格不碰任务质量的结构性保证）；
- 行为型（可靠）：行为模式层——承诺兑现、错误承认、不装懂。不做成语气（“稳重腔”是语义漂移）。验证 = 批级行为判据混合判定（本轮明确，见修订 2）。

### 1.2 单一派生链：trait → OCEAN → 参数包，禁止双通路

现状：persona 同时存 `ocean_json` + `traits_json`（`engine.py:335`）。裁决：规范化数值 OCEAN 向量是内部事实源，trait 是入口/展示层，派生方向唯一。DB/API/UI 的 `0..100` 位置数组与 YAML 的全名键 `0..1` 映射保留各自边界格式，统一归一化为 `OceanVector` 后参与派生。一致性 lint fixture 含两层：运行时派生链检查 + 展示层映射一致性检查（本轮新增，见修订 7）。存量迁移按 §8.2 保全用户手写标签后，将 `traits_json` 转为 OCEAN 派生展示缓存并废弃 traits 直驱通路；扩展规则：新增 trait 必须先定义 OCEAN 档位。

### 1.3 开放调节定位：本批 = 标定批

风格空间连续，5 trait = 空间中 5 个全验证标定点；开放调节批（OCEAN 滑杆 + 维度语料库 + 双轨注入）记候选池。三条架构决策：

- 语料库按维度组织：基础单元 = 维度×档位微型对话（本轮形态修正：2–3 轮，非单轮）；人格语料 = 维度引用组合 + 结构样本（诚实轮/纠偏轮/降档轮，`display_name` 参数化）+ 少量人格专属整轮演示。形态裁决以 P1 微型预实验数据为准（见修订 1）——数据先行，不裸奔拍板；
- 参数包按维度连续定义：每维每档参数增量（E 高 → temperature +δ、N 高 → hedging 档），人格 = 维度叠加，天然支持任意向量推导；
- OCEAN 向量 UI 可编辑性预留：schema + 校验按可编辑设计，初版可只读交付。

双轨同构：开放批风格调节 = AutoRouter 模式第三次应用——本地轨示例驱动逼近（保真度以 P4 组装形态数据为准），云端轨指令直达；OCEAN 向量为模型无关意图表示。

成本三条（开放批预注册心智）：空间中段保证强度低于标定点；验证锚点式 + 维度单调性检查；用户自定义“四不像”需 UI 引导。

## 6. Gate 验收（预注册）

### 6.1 盲判矩阵（风格型）

- 协议：外部 2–3 名非项目人员 pairwise forced-choice，200 对抽 100 子集；TA 盲评为参考列；
- gate = 逐对方向判定：每对正确率对随机 50% 显著（置信检验）+ 70% 参考列（预注册参考线，非统计推导）+ 混淆矩阵全量报告；
- 任一对方向不显著 → 该对降级路径（trait 对粒度：参数包微调档 / 与近邻合并记档）；TA-外部差值 > 15pp → 判例歧义性复查协议。

### 6.2 红线 Gate（全人格）

审计保护区逐字节一致（复用 W5 断言）；T 子集 12 判据 = baseline；攻击词表判例 0 命中（含对抗性）；S07/S09/M08 事实等价全人格过；L4 fixture 召回/误报达预注册目标。

### 6.3 回退 Gate

约束层关闭（层开关语义 A）= 同 seed 无约束路径逐字节一致；全功能一键回退。

### 6.4 开放风险预注册

1.5B 风格区间表达力是本批最大开放风险——锚点语料对比度拉满（用词/句长/标点全维度差异化）仍不达线，则部分 trait 诚实降级为“参数包微调”记档，不装可辨。

- 红线 gate：攻击性词表 0 命中 + 审计保护区逐字节一致（全人格）+ T 子集 = baseline（全人格）+ S07/S09 全人格过；
- 回退 gate：人格约束关闭（回 default persona）= 输出与 default 逐字节一致。

## 8. 前置依赖与 TA 锚定答案

P1 启动前四项阻塞锚均已确认，以下答案随本文件冻结。

### 8.1 `ocean_json` 字段顺序、取值域与档位定义

**Repo trace**：`ocean_json` 当前为固定位置数组 `[O,C,E,A,N]`，值为 `0..100` 整数；DB payload、API 与 UI 沿用该数组。YAML 不是数组，而是 `openness` 等全名键的 `0..1` 数值映射；两条加载路径最终都转换为 `OceanVector`。

**裁决**：v1 以规范化数值 OCEAN 向量为唯一语义事实源，不迁移为枚举 JSON；现有 DB 数组与 YAML 映射边界格式均不迁移。

1. 新增唯一维度顺序常量 `OCEAN_DIMENSION_ORDER = ("O", "C", "E", "A", "N")` 与名称→索引映射；所有按 index 取维度的实现改走该入口，禁止散装位置常量。
2. 新增单点派生函数 `to_level(dimension, value) -> "low|mid|high"`，供 L2 参数包与展示映射复用。
3. 档位初值冻结为：`0..33 = low`、`34..66 = mid`、`67..100 = high`。P1 必须覆盖 33/34、66/67 边界测试。
4. 切点属于预注册初值；仅允许 P4 判别数据在既定重校协议下调整，调整只改派生常量，不改规范化数值事实源或 DB/API/UI/YAML 边界格式。
5. “风格型 C 维全部中位”以 `to_level("C", value) == "mid"` 做确定性校验。

### 8.2 `traits_json` 消费方、兼容义务与迁移

**Repo trace**：消费方为 DB payload/API/前端展示；Skill/Plugin 无直读。现有 UI 允许手工编辑 traits 并回写 DB，新建人格才从 OCEAN 自动派生。YAML 将 `traits` 或 `tone_keywords` 映射为展示标签，而 `tone_keywords` 另有 reformatter 运行时消费方。

**裁决**：“纯派生缓存、无兼容义务”不成立。目标态仍是 OCEAN 单一事实源与 traits 派生展示缓存，但兼容义务落在迁移动作：

1. 迁移前将全部用户手写 traits 原文导出到本地用户数据目录中的一次性 JSON，并在 UI 明示“风格标签已转换，原文已导出”；不得静默覆盖用户创作物。
2. 不为废弃的 traits 直驱通路新增永久保留字段；导出物只承担数据保全与用户取回，不参与运行时派生。
3. 移除现有人格 traits chip 手工编辑与回写入口；traits 展示统一由 OCEAN→traits 映射函数生成。用户自定义风格的正路是后续 OCEAN 调节，不保留旁路。
4. `tone_keywords` 与展示 traits 分离命名空间：前者是 reformatter 行为配置，后者是可重建展示缓存，不得互作 fallback。
5. P1/P3 lint 必须验证运行时派生链与展示映射一致性；迁移脚本需幂等，并校验导出数量与迁移前手写记录数量一致。

### 8.3 W3 编号、范围与时序

**编号裁决**：W3 = 输出侧检测与跨轮结构批。

- 检测域主体：C 臂改为输出侧检测优先，输入侧身份意图只承担提醒注入；保留 4-gram 为独立复读度量并重校红线；扩展 P36 本地存储能力/事实错误与 P39 陪伴关系角色否认检测域。
- 结构域独立子批：修复 B 跨轮复读结构；保留 S16-S18 多轮相对优势，题库权重向聊天单轮失败面倾斜，修复后重跑盲评。
- 验证输入：true→retry/fallback 动作链测试、F2-c `366/370` 非身份负控基线、P29 跨 seed 稳定样本及 P36/P39 伴随样本。
- 不入 W3：参数包归 P 批 L2；偏好记忆与情绪调制进入开放调节批；v1.8.x 语义去重、reranker、模型升级等保持独立候选池。

**时序裁决**：P1–P4 先完成并锁定 L2/L4 形态。W3 可预先维护范围骨架，但正式规格与数值 gate 只能在 P4 矩阵后锚定。W3 形成可上线能力后使用 v1.9.0；W3 收口事件触发案例库三合一批，不依赖版本号或 patch 发布。

### 8.4 persona 切换 UX 与会话边界

**Repo trace**：UI 已有切换入口；激活 API 会立即替换当前 runtime 的 `session_core`，不创建新会话；API 失败时前端仍本地标记“已切换”。现状同时存在同会话热切和视觉假切换。

**裁决**：P3 必须把 UX 修复与人格约束接线同批交付。

1. persona 切换以新会话为硬边界：用户确认后自动创建新会话，或明确要求先开新会话；禁止在当前会话原地替换 `session_core`。
2. 前端状态由后端成功响应驱动。API 失败必须保留原 chip、原 persona 与原 session，显示错误；禁止本地 fallback 假成功。
3. 激活 API 的成功响应必须返回实际生效的 persona 与新 `session_id`（或明确的 `requires_new_session` 契约），不存在“已选中但未生效”的第三态。
4. 更新已激活 persona 当前也会热重建 `session_core`，必须纳入同一审查：编辑只影响后续新会话，不能污染当前窗口历史。
5. 移除 traits 编辑入口同时消除一条 active persona 编辑热重建路径；其余 name/OCEAN/anchor 编辑仍须遵守新会话生效契约。
6. P3 测试覆盖：正常切换创建新会话、取消切换保持原状态、API 失败回滚、应用重建后 active persona 一致、当前会话历史与 persona 不混搭。

与 model activate 债务的边界：model activate 不热重载是实现缺口；persona 不允许同会话热切是设计裁决。两者共同禁止“看起来切了实际没切”。

P2 启动前确认（非阻塞 P1）：

- 锚点语料的措辞规范与审核流程；
- 外部盲评人选（2–3 名非项目人员）与执行方式。
