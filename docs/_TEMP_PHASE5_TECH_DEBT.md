# Phase 5 技术债记录

本文件记录 Phase 5.2 为保持最小交付而暂不扩展的事项，不作为当前功能承诺。

- **后台通知持久化**：当前任务进度可通过计划卡片和状态 API 查看；窗口最小化后的系统通知、点击通知恢复窗口将在 5.3/后续 UI 壳能力中实现。
- **进度事件回放**：当前 API 从计划状态读取最新快照，尚未提供按 `trace_id` 或 `plan_id` 的进度事件回放；事件流重放与断线补偿保持在既有 SSE 链路中，后续统一接入。
- **复杂计划恢复**：当前进度查询不负责跨进程恢复执行，也不改变 PlanOrchestrator 的暂停/恢复语义；崩溃恢复和幂等重试需要单独设计验收。
- **实时推送统一化**：计划卡片仍兼容既有 SSE/事件处理路径，尚未抽取独立的前端 TaskProgress store，后续避免多个 UI 组件各自维护状态。
- **UI 标注交互面板**：5.5 当前完成标注会话、截图 API 和 Skill 包导出；截图上的拖拽框选、网格编辑器与多页面工作流仍需独立 UI 迭代。
- **OCR 能力接入**：特征生成 API 当前消费调用方提供的页面文字集合，尚未绑定 RapidOCR；OCR 依赖应保持可选，避免普通聊天安装被迫增大。
- **自动化执行入口**：导出的 manifest 使用本地 API 占位入口，尚未接入 PageLocator、UIActor、目标窗口硬锁和 A3 Consent 执行链，不能作为真实桌面操作能力宣传。
- **覆盖率本地验证**：当前开发环境缺少 `pytest-cov`，5.4 覆盖率门禁已接入 CI 依赖但尚未在本机生成真实报告。
- **桌面定位依赖**：5.6 的定位核心已支持注入 OCR/截图回调，`rapidocr-onnxruntime`、`mss`、`pynput` 仍是可选依赖，尚未在当前环境做真实屏幕验证。
- **操作执行链**：PageLocator 与 PageIdentifier 已完成纯逻辑能力；UIActor、目标窗口硬锁、跳转后的缓存失效接线和 A3 Consent 执行流程留待 5.7/后续阶段。
- **真实桌面 E2E**：5.7 当前完成注入式序列执行、序列级 Consent、danger 二次确认、中断与事件审计；pynput UIActor、前台窗口句柄校验和微信真实 E2E 仍需在桌面环境验收。
- **PluginFiber 接线**：manifest 能力检查已实现为非阻断 warning，但 UI 自动化服务尚未注册为 Phase 4 PluginFiber 的正式 provider，待后续插件接线阶段完成。
